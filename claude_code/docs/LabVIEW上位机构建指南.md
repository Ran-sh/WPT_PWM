## 第二章: 创建类型定义 (.ctl)

类型定义像一个"自定义数据结构"。多个 VI 共用它，改一处全局更新。

> ⚠️ **本章三条铁律——违反任意一条都会导致后续全部翻车:**
>
> **铁律 1**: 全程在**前面板** (灰色背景) 操作。**禁止按 Ctrl+E 去程序框图！**
>
> **铁律 2**: 用**控件面板 → 簇、类与变体 → 簇** (方框图标)，不是"类" (齿轮图标)！点错会创建 `.lvclass` 文件，整个项目无法使用。
>
> **铁律 3**: 控件先放在簇**外面**，再**拖进**簇外壳里。不要在程序框图上用捆绑函数连线。

### 2.1 创建遥测数据簇 — Data Cluster.ctl

#### 步骤 1: 新建类型定义

1. 项目浏览器中，**右键** `TypeDefs` 文件夹 → **新建(N) → 类型定义(T)**
2. 打开灰色背景的新窗口
3. 按 **Ctrl+S** → 保存到 `TypeDefs\Data Cluster.ctl`

#### 步骤 2: 放一个空簇外壳

> ⚠️ **极其重要——看清楚再点！**
>
> 控件面板 → **簇、类与变体** 这个子面板里，并列放着三个图标:
>
> | 图标 | 中文名 | 文件类型 | 我们要的是？ |
> |:---|:---|:---|:---|
> | 方框(有边框) | **簇** | `.ctl` | ✅ **就是它！** |
> | 立方体+齿轮 | **类** | `.lvclass` | ❌ 不要点这个！ |
> | 双色V形 | **变体** | (不是文件) | ❌ 也不要这个！ |
>
> **只点第一个——"簇"，图标就是一个简单的带边框方框。**

1. 在前面板空白处**右键单击**
2. 控件面板 → **簇、类与变体** → 点击**第一个图标** **"簇"** (带边框的方框，英文 Cluster)
3. **左键单击** → 在前面板上**按住左键**拖出一个矩形
4. 这就是一个**空簇外壳** (里面什么都没有，像一个空盒子)
5. 把空簇拖大一些 (约 3cm 高 × 4cm 宽)
6. 双击标签 → 改为 `Telemetry Data`

#### 步骤 3: 把控件拖进簇外壳里

**重要**: 先把独立的控件放在簇**外面**，再**拖进**簇里面。

1. 在簇外壳**外面**的空白处**右键单击**
2. 控件面板 → **数值 → 数值输入控件** → 放在簇**外面**
3. 双击标签 → 改为 `V`
4. **右键控件 → 表示法 → 双精度** (DBL, 橙色)
5. 默认值改为 `0.0`

同样的方式，在簇外面再放两个:
- `I` (电流): 数值输入控件，双精度 (DBL)，默认 `0.0`
- `F` (频率): 数值输入控件，**右键 → 表示法 → U32** (蓝色)，默认 `0`

6. 现在把三个控件**逐个拖进簇外壳**:
   - 鼠标点住 `V` 控件，**按住左键**，拖到簇外壳的**里面**
   - 松开 → V 控件进入簇内部，簇自动调整大小
   - 同样拖 `I`、`F` 进去
   - 如果簇不够大，拖动簇边框右下角拉大

7. 三个控件都在簇内部后，框选它们 → 工具栏 **左边缘对齐 + 垂直等距分布**

**确认**: 你的前面板上有一个簇 (Telemetry Data)，里面装着 V、I、F 三个控件。这就是类型定义。

> **为什么不在程序框图上用捆绑函数？**
> 因为 `.ctl` 类型定义本身就是"数据模板"。在前面板上直接把控件拖进簇 = 定义了数据结构。如果用捆绑函数在程序框图上拼，数据类型会变成"临时的"，其他 VI 引用时可能丢失类型信息。

8. 按 **Ctrl+S** 保存
9. 按 **Ctrl+W** 关闭

## 第三章: 搭建 TCP Server Core.vi (单次状态机)

> **关键设计**: 这个 VI **不包含 While 循环**。它每次被调用只执行一步操作 (初始化/监听/读取)，然后立即返回。循环由 Main.vi 的 TCP 循环负责。

**预计耗时**: 40-50 分钟

### 3.1 创建空 VI

1. 项目浏览器: **右键** "我的电脑" → **新建(N) → VI**
2. Ctrl+S → 保存为 `TCP Server Core.vi`

### 3.2 前面板

#### 输入控件

1. `Port`: 数值输入控件，U32，默认 8080
2. `Timeout (ms)`: 数值输入控件，I32，默认 100
3. `State`: 控件面板 → **下拉列表与枚举 → 枚举**，放在前面板
   - 右键枚举 → **编辑项...**
   - 插入 4 项: `Init`、`Listen`、`Connected`、`Error`
   - 点击**确定**
   - 标签改为 `State In`

4. `Listener ID`: 数值输入控件，I32，默认 -1
5. `Connection ID`: 数值输入控件，I32，默认 -1
6. `Error In`: 对话框与用户界面 → 错误输入3D.ctl

#### 输出指示器

7. `State Out`: 枚举 → 右键 → 编辑项 → 和上面一样 4 项 → 标签 `State Out`
8. `Listener ID Out`: 数值显示控件，I32
9. `Connection ID Out`: 数值显示控件，I32
10. `Connected?`: 圆形指示灯，打开颜色=绿色
11. `Remote Address`: 字符串显示控件，拖长
12. `Received Data`: 字符串显示控件，拖大
13. `Status`: 字符串显示控件，拖长
14. `Error Out`: 错误输出3D.ctl

#### 前面板布局

```
┌────────────────────────────────────────────────────┐
│  输入:                          输出:               │
│  Port: [8080]       State In:[ Init ▼]            │

│                      Received: [             ]     │

### 3.4 程序框图

按 Ctrl+E。

> **记住: 这个 VI 里不放 While 循环！**

#### 3.4.1 放条件结构

1. 搜索: `条件结构`
2. 放置，占程序框图约 80%
3. 把 `State In` 接线端**连到条件结构顶部的绿色 `?` 选择器**
4. 顶部标签变成 Init/Listen/Connected/Error

#### 3.4.2 Init 分支

1. 切换到 `Init`
2. 搜索: `TCP创建监听器` → 放置

3. **连线**:
   - Port → TCP创建监听器的 **port** (左上)
   - Error In → **error in** (左下)
   - TCP创建监听器的 **listener ID out** (右上) → Listener ID Out 指示器

4. 创建枚举常量 `Listen` → 连到 State Out

5. Connection ID Out = 创建常量 `-1`
6. Connected? = 创建假常量 (FALSE)
7. Remote Address = 创建空字符串常量
8. Status = 创建字符串常量 `"已初始化"`
9. Error Out ← TCP创建监听器的 error out

#### 3.4.3 Listen 分支

1. 切换到 `Listen`
2. 搜索: `TCP等待监听器` → 放置

3. **连线**:
   - Listener ID → **listener ID in**
   - 创建常量 `100` → **timeout** (100ms 足够，不阻塞)
   - Error In → **error in**

4. **判断有无连接**:
   - 搜索: `大于？`
   - TCP等待的 **connection ID out** → 大于？上输入
   - 创建常量 `0` → 大于？下输入
   - 如果 connection ID > 0: **有人连上了！**

5. **决定下一状态**:
   - 搜索: `选择`
   - 大于？输出 → 选择的 **s** (中间绿色)
   - 创建枚举常量 `Connected` → **t** (TRUE)
   - 创建枚举常量 `Listen` → **f** (FALSE)
   - 选择输出 → State Out

6. 连接信息:
   - TCP等待的 connection ID out → Connection ID Out (TRUE时)
   - TCP等待的 remote address out → Remote Address

7. Listener ID Out = Listener ID (不变)
8. Connected? = 大于？输出
9. Received Data = 空字符串
10. Status = `"监听中..."`
11. Error Out ← TCP等待的 error out

#### 3.4.4 Connected 分支 (核心——修复超时问题)

1. 切换到 `Connected`

2. 搜索: `TCP读取` → 放置

3. **重要——设置正确的超时时间**:
   - 创建常量 **`1500`** → 连到 TCP读取的 **timeout** 端子
   - **为什么是 1500ms？** 因为下位机每 1000ms 才发一次 JSON 数据。超时设 100ms 会导致每 0.1 秒报一次错误 56，LabVIEW 会把 TCP 连接错误计数累加，最终断开连接。1500ms 给下位机留足余量。

4. **连线**:
   - Connection ID → **connection ID in**
   - 创建常量 `512` → **bytes to read**
   - Error In → **error in**

5. **正确处理错误 56 (超时)**:
   - TCP读取的 **error out** → 我们需要检查错误代码
   - 搜索: `按名称解除捆绑` (因为错误簇里有 status/code/source 三个字段)
   - 把 error out 线连到按名称解除捆绑
   - 拉出 **code** 字段 (I32)
   - 搜索: `等于？`
   - code → 等于？上输入，创建常量 `56` → 下输入
   
   **如果 error code = 56 (超时)**:
   - 这是**正常情况**——只是这轮没数据而已
   - 不改变状态，Connected? 保持 TRUE
   - 搜索: `选择` → code=56 ? 用选择来:
     - TRUE (56错误): 清除错误 (用空错误簇)，状态保持 Connected
     - FALSE (其他错误): **真的断开了** → 关闭连接 → 状态变 Listen
   
   > 简化做法 (推荐): 判断 data out 是否为空字符串来决定是否断开，而不是依靠错误码。

**简化版逻辑 (推荐新手使用)**:

```
a. TCP读取的 data out → 搜索 字符串长度
b. 字符串长度输出 → 搜索 大于？ → 下输入 = 常量 0
c. 搜索 选择:
   - 选择器: 字符串长度 > 0
   - TRUE → data out (有数据) → Received Data 指示器
   - FALSE → 空字符串 → Received Data 指示器
d. 检查是否真的断开了 (不是超时):
   - 搜索 不等于？ → 比较 error code 和 56
   - 如果不是 56 且不是 0 (真的有错误):
     → 搜索 TCP关闭连接 → 关闭 Connection ID
     → State Out = Listen
     → Connected? = FALSE
   - 否则:
     → State Out = Connected
     → Connected? = TRUE
e. 用 选择 函数来处理两个分支
```

6. Connection ID Out = Connection ID (不变)
7. Listener ID Out = Listener ID (不变)
8. Status = `"已连接"`
9. Error Out ← 处理后的错误 (56 被清除，其他错误保留)

#### 3.4.5 Error 分支

1. 切换到 `Error`
2. 搜索: `TCP关闭连接` → 放两个，分别关闭 Listener ID 和 Connection ID
3. State Out = `Init`
4. Connected? = FALSE
5. Listener ID Out = -1
6. Connection ID Out = -1
7. Error Out ← error in (传递出去)

#### 3.4.6 最终检查

- [ ] 按 **Ctrl+B** 清除断线
- [ ] **确认没有放 While 循环！**
- [ ] 4 个分支都有 State Out 连线
- [ ] TCP读取的超时是 1500
- [ ] Connected 分支处理了错误 56
- [ ] 所有输出指示器在每个分支里都有连线

b. 连线:
   - element → JSON String
   - V/I 阈值控件 → 对应的 Threshold 输入
   - F Min/Max → 对应的输入

c. 输出:
   - V → V 显示
   - I → I 显示
   - F → F 显示
   - P → P 显示
   - 报警信号 → 对应 LED

d. 更新波形图表:
   - 搜索 捆绑 → V, I, F, P 按顺序包起来
   - 捆绑输出 → 波形图表终端
   - Chart 自动累积，不超过300点

e. 通讯超时:
   - 搜索 时间计数器(ms) → 获取当前毫秒
   - 用移位寄存器存上次收到数据的时间
   - (当前 - 上次 > 5000) → 通讯中断 = TRUE
   - 收到数据 → 更新上次时间，通讯中断 = FALSE

f. TDMS 数据记录 (循环内只写入):
   - 搜索 条件结构 → 选择器连 "启用记录"
   - 真:
     - 搜索 TDMS写入
     - tdms file: 第3对移位寄存器的 TDMS 引用
     - group name: 字符串 "Telemetry"
     - channel names: 数组 ["V", "I", "F", "P"]
     - data: 创建数组 [V, I, F, P]
     - tdms file out → 第3对移位寄存器 (传给下次)
     - 已记录行数 +1
   - 假: TDMS 引用直接穿过
```

**真 (超时)**:
- 什么都不做
- TDMS 引用穿过

**步骤 5**: 在循环外 (右边) 关闭 TDMS

循环右边的外部:
- 搜索 `TDMS关闭` → 连入第3对移位寄存器传出的 TDMS 引用
- 如果有错误: 连到简易错误处理器

**步骤 6**: 停止条件
- (停止按钮 AND 数据队列为空) OR 错误

2. 搜索 `释放队列` → 释放指令队列

## 附录B: 新手排错指南

### 问题 1: 线连不上 (黑色虚线)

**线的颜色对应类型**: 橙色=浮点数，蓝色=整数，绿色=布尔，粉色=字符串，紫色=引用，黄色=错误簇

**解决**: 类型不同 → 搜索转换函数。或 Ctrl+B 清除重试。

### 问题 2: 运行按钮灰色 (断裂箭头)

点工具栏断裂箭头 → 错误列表 → 双击跳转。常见: "包含未连线端子"。

### 问题 3: UI 点击没反应 / 窗口白屏

**原因**: 在事件结构的超时分支里放了阻塞代码 (如带 While 循环的子 VI)。

**解决**: 使用三并行循环架构——事件循环只处理按钮，TCP 循环单独跑。

### 问题 4: TCP 频繁断开 (错误 56/60)

- 错误 56: 超时 → 检查 TCP读取 超时设了 1500 (不是 100!)
- 错误 60: 端口占用 → 关 NetAssist
- 错误 66: 连接被关 → 下位机断开了，固件检查 WiFi

### 问题 5: JSON 解析结果全是 0

捆绑常量的标签名必须与 JSON key 完全一致 (大写 V、I、F)。

### 问题 6: TDMS 文件损坏 / 硬盘灯狂闪

**原因**: 在循环内每次打开关闭文件。

**解决**: 文件打开放循环外左边，关闭放右边，循环内只写入。

### 问题 7: LabVIEW 卡死

Ctrl+Alt+Del → 任务管理器 → 结束 LabVIEW.exe。如果 VI 损坏: 项目浏览器中右键 VI → **还原...**
