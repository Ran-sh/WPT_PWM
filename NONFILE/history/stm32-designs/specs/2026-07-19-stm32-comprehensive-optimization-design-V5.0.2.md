# STM32 V5.0.2 全面审查与分阶段优化设计

> 日期：2026-07-19
>
> 目标分支：`5.0`
>
> 目标版本：`V5.0.2`
>
> 适用范围：`Keil_Project/Hardware/`、`Keil_Project/System/`、`Keil_Project/User/`

## 1. 背景

V5.0.1 已完成 GPIO 全量重映射、五键系统和四灯系统，但对 33 个 STM32 `.c/.h` 文件进行全量静态审查后，确认仍存在多项会影响功率安全、Flash 数据完整性、SPI 稳定性和长期维护的问题。

本轮采用“安全优先、分阶段优化”的方式处理全部已确认问题。每一阶段均要求独立可编译、可验证、可回退，禁止将安全修复、存储格式迁移和大范围代码整理混在同一个不可定位的改动中。

当前基线构建记录：

- ARMCC V5.06 update 5，0 Error、0 Warning。
- ROM：52272 B，约 51.05 KB / 64 KB。
- RAM：5560 B，约 5.43 KB / 20 KB。
- 必须控制新增代码体积，最终仍需保留合理 Flash 和 RAM 余量。

## 2. 已确认的主要问题

### 2.1 功率与状态安全

1. `SYS_STATE_SWEEP` 已经输出 PWM，但过流保护只在 `SYS_STATE_RUNNING` 生效。
2. PB10 关闭时，本地 KEY4 和远程 `CMD:ON` 仍可直接启动 PWM。
3. KEY0 在 FAULT 中调用普通 Stop，会把逆变器内部状态改为 IDLE，削弱故障锁存语义。
4. UI、网络层直接调用逆变器启动/停止并直接修改全局状态，缺少统一联锁入口。
5. TIM1 频率更新在 `UDIS=1` 时写 `UG`，与“立即同步装载影子寄存器”的注释不一致。
6. ADC 数据失效没有运行时检测，保护逻辑可能继续使用旧值。

### 2.2 W25Q128 与黑匣子

1. `Blackbox_Entry_Packed` 字段实际合计 12 B，但 `BLACKBOX_ENTRY_SIZE` 定义为 14 B，形成对象越界读写。
2. CRC8 计算长度包含尚未初始化的 CRC 字节，读取校验基本无法成立。
3. 元数据与日志共用第一个 4 KB 扇区，保存元数据会擦除同扇区日志。
4. 循环日志回绕后未先擦除目标扇区，NOR Flash 无法把 0 重新写成 1。
5. 运行时元数据保存尝试擦除扇区，但底层 L4 禁止擦除后仍继续页写，调用方无法知道失败。
6. 故障快照可能跨 256 B 页边界，却仍调用单页写接口。
7. 当前“前 5 秒 + 后 5 秒”在故障触发瞬间同步写入，实际上没有后 5 秒数据。
8. 上电恢复读取未初始化局部缓冲；只校验写指针，未完整恢复序号和其他元数据。
9. W25Q Busy 超时为 100 ms，短于 W25Q128JV 4 KB 扇区擦除 400 ms 最大值。

### 2.3 SPI1 分时复用

1. TFT 使用全双工 SPI 发送后不清 RXNE/OVR，切换到 Flash 时可能读取旧数据。
2. TFT 和 Flash 分别操作 SPI1、DFF、PA6 和 CS，缺少唯一总线所有者。
3. 多个轮询等待没有统一超时和恢复路径。
4. W25Q 驱动依赖 TFT 驱动提前打开 GPIOB 并锁高 PB12，模块自包含性不足。

### 2.4 ADC、调度与校准

1. ADC 硬件实际连续转换，软件仅每约 2 ms读取最新值，“按 144241 CPU 周期触发 ADC”的说明不准确。
2. 主循环延迟超过两个周期时直接弃样，TFT/Flash 操作可能造成持续弃样。
3. 冷启动校准只调用一次，但校准状态机需要窗口填满并累计 50 次，实际没有完成。
4. Safety EMA 每圈主循环更新，时间常数依赖主循环负载，与文档描述不一致。
5. 显示滤波和安全滤波共用慢通道，会推迟过流响应。
6. 电压增益参数已保存但未真正参与计算。
7. 负电流转换为无符号黑匣子字段时可能溢出。

### 2.5 按键、网络和 UI

1. UP/DOWN 被配置为支持双击，普通单击额外等待约 200 ms。
2. KEY0、BACK、UP、DOWN 都可能产生不需要的长按事件。
3. KEY4 长按清除 WiFi 当前是全局行为，不只限于 WiFi 配置页。
4. STM32 发送 `g_sys_state`，RUNNING 值为 3；ESP8266 现有协议使用 `S==2` 判断运行，云端会误判停机。
5. 遥测被当前 TFT 页面和扫频状态关闭，无法持续反映系统物理状态。
6. USART2 发送无限等待 TXE，没有超时，也会阻塞主循环。
7. PA12 已改为普通 GPIO，背光只支持开/关；现有亮度 1～100%、手动亮度和呼吸灯页面均为无效功能。

### 2.6 可维护性

1. 多处声明位于语句之后，依赖 ARMCC 扩展，不符合项目 C89 约束。
2. 注释中仍存在旧引脚、旧版本和错误时序描述。
3. 四个运行状态函数重复调用相同任务，任务顺序不统一。
4. 多个驱动接口使用 `void` 静默失败，应用层无法采取降级措施。

## 3. 目标与非目标

### 3.1 目标

- 建立 PB10、PWM、状态机和故障之间的强制联锁。
- 扫频和运行期间都具备确定周期的快速过流保护。
- 修复所有已确认的黑匣子越界、CRC、擦除和掉电恢复问题。
- 建立 SPI1 唯一所有者，消除 TFT/W25Q128 切换残留状态。
- 让 ADC 采样、校准和安全检查具有固定时间基准。
- 让五个按键严格符合 V5.0 已确认交互规则。
- 保持本地功能独立于网络，网络故障不能阻塞功率控制。
- 保持 `main.c` 简洁，只承担初始化和状态分发。
- 全项目 STM32 代码统一为 V5.0.2，ARMCC V5 0 Error、0 Warning。

### 3.2 非目标

- 不修改 SPL V3.5.0、CMSIS 和启动文件。
- 不改变 95～150 kHz、50% 占空比、1000 ns 死区等 PWM 基线。
- 不修改 PCB 引脚定义。
- 不新增 TFT 大功能页面。
- 不修改 OneNET Web、小程序业务逻辑。
- ESP8266 只作为协议兼容性验证对象，本轮不主动改其业务代码。

## 4. 总体方案

采用四阶段实施：

1. 安全与功率联锁。
2. SPI1、W25Q128 和黑匣子。
3. ADC、调度、按键和网络。
4. 结构整理、文档同步和全量回归。

每阶段完成后执行：

- 检查本阶段 diff。
- Keil 全量编译。
- 检查 ROM/RAM 变化。
- 执行对应硬件冒烟测试。
- 独立提交，不夹带用户现有未提交文件。

## 5. 安全控制设计

### 5.1 状态封装

系统状态不再允许 UI 和网络层直接写入。`Sys_Core` 成为唯一状态所有者，对外提供：

- 获取当前状态。
- 请求启动。
- 请求正常停止。
- 请求故障复位。
- 查询 12 V 电源状态。
- 触发带原因的故障关断。

建议结果类型：

- `SYS_CONTROL_RESULT_OK`
- `SYS_CONTROL_RESULT_POWER_OFF`
- `SYS_CONTROL_RESULT_FAULT_LATCHED`
- `SYS_CONTROL_RESULT_ADC_NOT_READY`
- `SYS_CONTROL_RESULT_INVALID_STATE`

建议故障原因：

- `SYS_FAULT_NONE`
- `SYS_FAULT_OVERCURRENT`
- `SYS_FAULT_ADC_STALE`
- `SYS_FAULT_CONTROL_INVARIANT`

### 5.2 启停规则

| 操作 | 结果 |
|:---|:---|
| KEY0 开启 | PB10=HIGH，POWER=ON，不启动 PWM |
| KEY0 关闭 | 先停 PWM，再 PB10=LOW，POWER/STATUS=OFF |
| KEY4 启动 | 仅 PB10 开启、ADC 就绪、无故障且状态允许时进入 SWEEP |
| KEY4 正常停止 | 停 PWM并回 IDLE，PB10 和 POWER 保持开启 |
| `CMD:ON` | 与 KEY4 使用同一个启动接口和联锁条件 |
| `CMD:OFF` | 只正常停止 PWM，不越权关闭 KEY0 控制的 12 V |
| 过流/ADC失效 | 立即停 PWM、拉低 PB10、熄灭 POWER/STATUS并锁存 FAULT |
| FAULT 中按 KEY0 | 不允许重新开启 12 V |
| FAULT 中按 KEY4 | 清故障回 IDLE，但 PB10 继续保持 LOW |

### 5.3 故障动作顺序

1. 禁止 TIM1 MOE。
2. 停止 TIM1 计数。
3. 取消软启动和频率斜坡。
4. PB10 拉低关闭 12 V。
5. POWER、STATUS 熄灭。
6. 记录故障原因并切换到 FAULT。
7. 启动黑匣子故障后采样流程。
8. 蜂鸣器进入故障提示模式。

CPU Fault Handler 保留直接寄存器紧急关断，不调用普通应用层状态机。这样在栈、堆或模块状态已经损坏时仍能关闭 TIM1 和 PB10。看门狗随后负责复位。

### 5.4 TIM1 频率更新

更新 ARR/CCR 时遵守 STM32F1 更新事件规则：

- 写预装载寄存器期间禁止产生中间更新。
- 写完后恢复 Update Event，再产生一次 UG。
- ARR、CCR1、CCR2 在同一个更新边界生效。
- 保持偶数周期计数，避免全桥两半周不对称。

不得继续使用“UDIS 保持为 1 时写 UG并认为已完成影子装载”的顺序。

## 6. ADC 与安全采样设计

### 6.1 硬件采样

TIM3 作为 2 ms ADC 触发时基：

- TIM3 更新事件：500 Hz。
- ADC1 扫描 PB0/CH8 电流和 PB1/CH9 电压。
- DMA1 Channel1 搬运一对采样值。
- DMA完成路径只复制两个半字并递增序号，不做浮点计算。
- 主循环根据新序号执行滤波和物理量换算。

这会替代当前“ADC连续转换 + DWT定时读取最新值”的不确定模式。TIM3 在当前工程中未被业务使用。

### 6.2 双通道滤波

- 显示通道：64点滑动窗口，供 TFT 和遥测使用。
- 安全通道：8点短窗口，仅供保护使用。
- 安全任务每 2 ms检查一次。
- 连续3次安全电流超过 5.0 A 才触发过流故障。
- 单个尖峰不会直接锁存，持续过流能在短时间内关断。
- 负电流钳位为 0；异常超范围值进入诊断，不允许无符号溢出。

### 6.3 数据失效

- 保存最近一次有效 ADC 序号和时间。
- 超过 20 ms没有新采样：
  - IDLE：禁止启动。
  - SWEEP/RUNNING：触发 `SYS_FAULT_ADC_STALE`。
  - FAULT：保持故障锁存。

### 6.4 冷启动校准

- Flash 校准值通过范围和 CRC校验时，ADC立即就绪。
- 校准无效时，PB10保持关闭。
- 先填满采样窗口，再每 10 ms累计一次零点，共 50次。
- 校准完成后设置 ADC Ready，允许启动。
- 新校准值在 IDLE 状态进入待保存队列。
- 电压增益实际参与换算；无效增益回退 1.0。

## 7. SPI1 共享总线设计

新增唯一 SPI1 共享总线控制层，职责包括：

- 初始化 SPI1 Mode 3、18 MHz。
- 管理 TFT 8-bit、TFT 16-bit DMA、W25Q 8-bit 三种模式。
- 管理 PA6 的 TFT_DC 输出和 Flash_MISO 输入角色。
- 切换前等待 BSY 清零。
- 清除 DR、RXNE 和 OVR 残留。
- 先锁高 TFT_CS、W25Q_CS，再切 DFF和GPIO方向。
- 保证任一时刻最多一个 CS 为 LOW。
- 超时后强制释放两个 CS并恢复 PA6 为 TFT数据态。

TFT DMA仍由 `Tft_Driver` 负责像素传输，但模式切换和总线恢复必须走共享层。W25Q 驱动不得再依赖 TFT 驱动提前配置 PB12或GPIOB时钟。

## 8. W25Q128 接口设计

### 8.1 状态返回

读、写、擦除接口返回明确状态：

- OK
- NO_DEVICE
- INVALID_ARGUMENT
- OUT_OF_RANGE
- PAGE_CROSS
- ERASE_BLOCKED
- SPI_TIMEOUT
- BUSY_TIMEOUT
- VERIFY_FAILED

通用写接口负责自动跨页拆分；单页写下沉为内部实现。调用方不能再用 `void` 接口静默失败。

### 8.2 超时

- SPI单字节等待使用短微秒级超时。
- Page Program 使用 10 ms保护超时。
- 4 KB Sector Erase 使用 500 ms保护超时。
- 超时后 CS必须拉高，总线必须归还 TFT。

### 8.3 地址守卫

- 所有读写检查 `addr + len` 溢出和16 MB边界。
- 扇区擦除地址向下对齐到4 KB。
- 页写内部保证不跨256 B边界。
- 发波期间禁止扇区擦除，但允许有界页写日志。

### 8.4 依赖边界

W25Q底层驱动只负责Flash和SPI协议，不再包含`Sys_Core.h`或`App_Storage.h`：

- 发波禁擦由系统控制层设置底层擦除锁，驱动只检查锁状态。
- CRC32移入独立的系统校验工具，供配置、元数据和字库头共同使用。
- `Font_Header`及字库格式校验归属TFT字库层，不再由原始Flash驱动解析应用数据。
- 删除`Tft_Driver_Font_Init()`和`Font_Header_Load()`之间的重复校验实现，只保留一个入口。

这样保持“应用存储依赖Flash驱动”，不再出现“Flash驱动反向依赖应用存储”的循环分层。

## 9. 配置存储设计

配置 A/B区域地址保持不变，保留用户现有 WiFi、校准和界面设置。

保存过程：

1. 复制配置并对整个结构先清零，避免填充字节不确定。
2. 校验字段范围，计算 CRC32。
3. 擦除 A、写A、回读并验证A。
4. 只有A验证成功后才擦除和写B。
5. 回读B并验证。
6. 任一步失败都保留RAM配置并返回错误。

现有Flash工具链使用非反射CRC32：多项式`0x04C11DB7`、初值`0xFFFFFFFF`、最终异或`0xFFFFFFFF`。V5.0.2保持该算法，避免破坏已有配置和字库头兼容性；只修正“与zlib/WinRAR一致”的错误注释，并增加固定测试向量验证。

运行中修改设置时只更新 RAM并标记待保存。回到 IDLE 后由 `App_Storage_Task()` 完成持久化。

PA12为普通GPIO，无法输出背光PWM。因此：

- 删除亮度子菜单。
- 删除手动亮度页。
- 删除呼吸灯页。
- TFT初始化后背光常亮。
- 旧 `backlight` 字段暂时保留用于配置结构兼容，但不再提供无效UI功能。

设置菜单保留语言、字间距、图标和颜色。

## 10. 黑匣子 V2 设计

### 10.1 迁移规则

V5.0.1 黑匣子存在结构长度和CRC错误，不能可靠恢复。V5.0.2：

- 保留配置A/B。
- 不解析旧黑匣子日志。
- 元数据版本升级。
- 旧黑匣子区域按新格式惰性重新使用。
- 不在首次启动时整片擦除4 MB，避免长时间阻塞。

### 10.2 分区

| 区域 | 地址 | 用途 |
|:---|:---|:---|
| Metadata A | `0x310000~0x310FFF` | 元数据日志A |
| Metadata B | `0x311000~0x311FFF` | 元数据日志B |
| Circular Log | `0x312000~0x6CFFFF` | 普通运行日志 |
| Fault Slots | `0x6D0000~0x70FFFF` | 64个4 KB故障快照槽 |

### 10.3 日志记录

普通日志固定12 B：

| 字段 | 大小 |
|:---|---:|
| timestamp_ms | 4 B |
| voltage_x100 | 2 B |
| current_x1000 | 2 B |
| frequency_hz | 2 B |
| system_state | 1 B |
| crc8 | 1 B |

CRC8只计算前11 B。使用编译期断言保证结构大小严格等于12 B。

### 10.4 元数据双日志

元数据记录包含：

- magic和格式版本。
- generation。
- 当前写偏移。
- 有效记录数。
- 环绕次数。
- 下一个故障槽。
- 丢弃记录数。
- CRC32。

启动时扫描A/B两个4 KB扇区，选择 generation最高且CRC有效的记录。活动扇区写满后，仅在 IDLE：

1. 擦除另一个扇区。
2. 写入最新元数据。
3. 回读验证。
4. 验证成功后切换活动扇区。

任何时刻至少保留一个有效元数据扇区。

### 10.5 扇区生命周期

- 写入新日志扇区前必须确认该扇区已擦除。
- IDLE 后台任务预擦除后续扇区。
- SWEEP/RUNNING 中绝不执行扇区擦除。
- 运行时没有可写扇区时暂停记录并增加丢弃计数，不能覆盖未擦除数据。
- 页写失败不得推进写指针和序号。

### 10.6 故障快照

- RAM维护25条、共5秒的故障前环形记录。
- 故障发生后继续采集25条、共5秒的衰减数据。
- 组合为50条记录，约600 B。
- 每次快照独占一个4 KB扇区槽。
- 快照包含头部、故障原因、序号、50条记录和CRC32。
- 64个槽循环使用，擦除只发生在 PWM和PB10均关闭的FAULT/IDLE状态。
- 若故障后5秒内复位，尚未写入的后半快照可能丢失；安全关断优先于同步写Flash。

## 11. 按键设计

驱动配置拆分为独立能力标志：单击、双击、长按。

| 按键 | 单击 | 双击 | 长按 |
|:---|:---:|:---:|:---:|
| KEY0 / PB9 | 电源切换 | 无 | 无 |
| KEY1 / PB8 | 返回上一级 | 返回主菜单 | 无 |
| KEY2 / PB7 | UP/加 | 无 | 无 |
| KEY3 / PB6 | DOWN/减 | 无 | 无 |
| KEY4 / PB5 | 确定/启停 | 无 | 仅WiFi配置页有效 |

UP/DOWN不再进入双击等待，释放去抖完成后立即产生CLICK。现有亮度页UP/DOWN长按逻辑随无效背光页面一起删除。

KEY4长按只有在 WiFi配置页、PWM未运行时才能发出清除配置流程；其他页面长按不产生业务行为。

## 12. 网络与USART2设计

### 12.1 TX环形缓冲

- USART2发送改为TXE中断驱动。
- 固定静态环形缓冲，不使用动态内存。
- 入队接口返回成功、队列满或参数错误。
- ISR只发送一个字节、推进指针并管理TXE中断。
- 串口异常不会无限阻塞主循环。

### 12.2 遥测协议

在线时每500 ms发送一次，不再受当前TFT页面限制。

| 系统状态 | 协议S | F |
|:---|---:|---:|
| IDLE | 0 | 0 |
| SWEEP | 1 | 当前扫频频率 |
| RUNNING | 2 | 当前运行频率 |
| FAULT | 3 | 0 |

V/I始终使用有效的显示滤波物理量。协议S与内部 `Sys_State` 分离，通过显式映射生成，保证ESP8266现有 `S==2` 运行判断正确。

远程 ON/OFF调用与本地KEY4相同的系统控制接口。远程命令不能绕过PB10、ADC Ready和FAULT锁存。

## 13. 调度与初始化设计

### 13.1 初始化顺序

1. NVIC分组。
2. 钳位ESP控制脚。
3. 预置PB10关闭并建立早期安全状态。
4. 初始化SysTick时间基准。
5. 初始化PWM、共享SPI/TFT、LED、蜂鸣器、ADC、按键。
6. 初始化W25Q128和字库。
7. 初始化配置与黑匣子元数据。
8. 显示开机画面。
9. 加载校准和UI设置。
10. 启用看门狗和ESP8266。
11. 进入IDLE。

TFT复位、SLPOUT、DISPON和LED自检改用准确毫秒延时，删除不准确NOP延时说明。

### 13.2 公共调度

每个状态统一调用公共任务，推荐顺序：

1. ADC数据处理和校准。
2. Safety检查。
3. Key FSM。
4. UI事件分发。
5. 当前状态专属任务。
6. Network任务。
7. Storage后台任务。
8. LED和Buzzer任务。
9. 看门狗刷新。
10. WFI等待中断。

状态专属任务只保留：

- IDLE：等待操作和后台Flash维护。
- SWEEP：软启动频率步进。
- RUNNING：目标频率斜坡。
- FAULT：故障后采样、快照提交和复位等待。

### 13.3 看门狗

IWDG设置为约1.6～2.4秒窗口。500 ms最大Flash扇区擦除仍在最短看门狗时间以内。调试模式继续暂停IWDG。

## 14. UI与TFT优化

- 删除3个无效背光页面及相关状态变量、字符串和存储操作。
- 页面枚举保持连续并同步所有switch。
- 顶部WiFi/MQTT图标仅在状态或动画帧变化时重绘。
- 保留增量刷新，减少不必要的全屏清除。
- SPI超时后标记显示故障并释放总线，不能拖死安全任务。
- TFT缺失或异常不允许影响PWM紧急关断。
- Splash版本号更新为V5.0.2。

## 15. 异常降级策略

| 异常 | 行为 |
|:---|:---|
| ADC超过20 ms无新数据 | IDLE禁启动；SWEEP/RUNNING进入FAULT并关12 V |
| W25Q不存在 | ROM字库、RAM默认配置、日志禁用，本地PWM可用 |
| Flash写失败 | RAM配置保留，标记待重试，不误报成功 |
| SPI/TFT超时 | 双CS拉高、总线复位、显示降级，安全任务继续 |
| ESP/USART异常 | 网络离线，本地控制继续 |
| HardFault等CPU异常 | 直接关TIM1/MOE和PB10，等待IWDG复位 |
| 控制状态不一致 | 安全停机并进入CONTROL_INVARIANT故障 |
