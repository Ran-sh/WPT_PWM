# WPT 微信小程序部署文档

**版本**: V5.1.2 | **更新**: 2026-07-26

## 一、正式部署（直连 OneNET）

1. 在微信公众平台创建小程序，将 AppID 写入 `project.config.json`。
2. 在“开发管理 → 服务器域名”中，将 `https://iot-api.heclouds.com` 加入 request 合法域名。
3. 用微信开发者工具上传代码，提交审核并发布。
4. 用户首次打开时，在设置页填写自己的 OneNET 产品、设备和 Token。

小程序本身不需要 Railway、ngrok 或自建服务器。

## 二、可选桥接服务

`安卓app/server` 用于非微信客户端或调试程序通过 HTTP 访问 MQTT。它不是小程序的默认数据链路。

### 1. 环境变量

| 变量 | 必填 | 说明 |
|:---|:---:|:---|
| `WPT_MQTT_BROKER` | 否 | MQTT地址，默认 `mqtt://broker.emqx.io:1883` |
| `WPT_DEVICE_NAME` | 否 | 设备名称，默认为占位值 `YOUR_DEVICE_NAME` |
| `WPT_BRIDGE_API_KEY` | **是** | `/cmd` 鉴权密钥，空值时禁止指令接口 |
| `WPT_ALLOWED_ORIGIN` | 否 | 允许跨域的前端源，默认不开放CORS |
| `PORT` | 否 | HTTP端口，默认3000 |

### 2. 本地启动

```powershell
cd 安卓app/server
npm install
$env:WPT_BRIDGE_API_KEY = '请替换为高强度随机密钥'
npm start
```

也可使用 `Claude_Files/tools/start_bridge.ps1`，它会生成随机 API Key、启动桥接和 ngrok，并仅记录本次启动的进程。`stop_bridge.ps1` 只停止这些已记录进程。

### 3. 接口

- `GET /health`：返回服务、MQTT和遥测时效状态。
- `GET /data`：返回最近一帧已校验遥测。
- `POST /cmd`：请求头必须带 `X-WPT-Key`，请求体例如 `{"cmd":"CMD:SETFREQ:99900"}`。

只接受 `CMD:ON`、`CMD:OFF` 和20–200kHz的 `CMD:SETFREQ:<Hz>`。低频档量化到100Hz，高频档量化到1kHz。MQTT离线时指令接口返回503，不会伪报下发成功。

## 三、上线安全检查

- 必须使用 HTTPS，禁止把 API Key、OneNET Token 或 MQTT 密码提交到仓库。
- 将 `WPT_ALLOWED_ORIGIN` 设为确切域名，不要使用 `*`。
- 为桥接进程设置重启策略，并在反向代理层增加请求频率限制。
- 对外发布前执行 `npm test`，并检查 `/health` 中的 MQTT 状态。
