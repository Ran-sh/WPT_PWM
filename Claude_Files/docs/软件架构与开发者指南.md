# 无线充电全桥谐振控制系统 — 软件架构与开发者指南

> **文档版本**: V4.1
> **适用硬件**: STM32F103C8T6 + ESP8266-01 + SSD1315 128x64 OLED
> **固件库**: STM32 标准外设库 (SPL) V3.5.0 + Arduino ESP8266 Core 3.x
> **编译工具链**: Keil MDK-ARM V5 (uVision) + Arduino IDE
> **协议**: OneNET MQTT 物模型 (Dual-MCU V4.1)

---

## 1. 系统概述

### 1.1 设计目标

本系统是一套基于 STM32F103C8T6 + ESP8266-01 双 MCU 架构的无线充电全桥谐振电源控制方案。STM32 作为"物理脑"负责 PWM 发波、ADC 采集、故障保护和人机交互；ESP8266 作为"联网脑"独立运行 Arduino MQTT 固件，通过 USART2 纯 JSON 串口透传与 STM32 通信，实现 OneNET 物联网平台的远程监控与控制。

### 1.2 Dual-MCU 双脑架构

```
┌──────────────────────────────┐    ┌──────────────────────────────┐
│         STM32 (物理脑)        │    │      ESP8266 (联网脑)         │
│  ─────────────────────────── │    │  ─────────────────────────── │
│  • PWM 发波 + PFM 调功        │    │  • WiFiManager 网页配网       │
│  • ADC 双通道采集 + 滤波       │    │  • OneNET MQTT 物模型连云     │
│  • KEY/OLED/LED 人机交互      │    │  • 串口 JSON ↔ STM32 透传    │
│  • 纯 JSON 串口透传           │    │  • WiFi/MQTT 自动重连         │
│  • 软启动扫频 + 过流保护       │    │  • 虚拟按键 FreqAdd/FreqSub   │
└──────────┬───────────────────┘    └──────────┬───────────────────┘
           │           USART2 115200           │
           │   纯文本 JSON (零 AT 指令)          │
           ├──────────────────────────────────►│
           │  {"V":12.50,"I":1.23,"F":100000}  │
           │◄──────────────────────────────────┤
           │  CMD:ON / CMD:OFF                  │
           │  CMD:F_UP / CMD:F_DOWN             │
```

**铁律**: STM32 绝不发送 AT 指令，ESP8266 绝不操作 PWM/ADC。通信协议为纯文本 JSON over USART2 115200bps。

### 1.3 功能清单

| 编号 | 功能模块 | 详细描述 |
|:---:|:---|:---|

### 1.4 程序启动流程

```
上电 → PWM_Init(MOE=OFF) → OLED_Init → LED_Init → ADC_DMA → KEY_Init
     → SysTimer_Init → OLED "Wireless Charge"
     → while(1):
         KEY_Task(10ms) | ADC_Filter_Task(2ms) | UI_Task(200ms)
         | App_Net_Task(2000ms遥测/实时轮询) | Inverter_SoftStart_Task(10ms)
         | LED_Task(500ms)

硬件初始化: KEY0 单击 → App_Net_Init(阻塞~3s, CH_PD 复位 + USART2 初始化)
            → ESP8266_IsReady()=1 → OLED "WiFi: READY"
扫频: KEY0 单击(SS_IDLE) 或 云端 CMD:ON → Trigger(150kHz) → 10ms/步→100kHz DONE(~2.5s)
关断: KEY1(SS_SWEEP) / KEY0(SS_DONE) / 云端 CMD:OFF → Stop → SS_IDLE
调频: KEY1(SS_DONE) +1kHz / 云端 CMD:F_UP +1kHz / 云端 CMD:F_DOWN -1kHz
每次 ON 都是全新扫频 150k→100k
```

```
         ┌──────────────────────────┐
         │   应用层 (Application)    │  User/main.c, User/App_Net.c
         ├──────────────────────────┤
         │   系统服务层 (System)      │  System/SysTimer.c
         ├──────────────────────────┤
         │   硬件驱动层 (Hardware)    │  Hardware/ESP8266, PWM, ADC, KEY, OLED, LED, UI

         └──────────────────────────┘
```

**层间依赖规则**: Hardware 层仅依赖 SPL 头文件; System 层依赖 Hardware; Application 层依赖两者。绝不反向。

## 2. 核心模块详解

### 2.1 SysTimer 时基总管

全局毫秒时间戳，全项目唯一时基源。`SysTick_Handler` 净化后仅含 `SysTimer_IncTick()` 一行。

**时间戳差值法 (核心调度模式)**:

```c
void Some_Task(void) {
    static uint32_t last = 0;
    if (SysTimer_GetTick() - last >= PERIOD_MS) {
        last = SysTimer_GetTick();
        // 周期业务逻辑
    }
}
```

利用 uint32_t 无符号减法自动处理 49.7 天溢出回绕。`SysTimer_DelayMs()` 仅供初始化阶段使用 (如 ESP8266 CH_PD 复位)，运行时严禁调用。

**公开接口**: `SysTimer_Init()`, `SysTimer_IncTick()`, `SysTimer_GetTick()`, `SysTimer_DelayMs(uint32_t ms)`.

---

### 2.2 PWM 驱动、防偏磁与软启动

#### 2.2.1 全桥拓扑

TIM1 高级定时器 `GPIO_PartialRemap_TIM1`，四通道互补输出。CH1=PWM1 / CH2=PWM2，相位差 180° 对角线导通。

#### 2.2.2 死区配置

```c
#define DEADTIME_NS  1000   // PWM.h — 修改此值调整死区
// TDTS = 13.889ns @ 72MHz CKD_DIV1
// DEADTIME_REG_VAL = ((DEADTIME_NS) * 72 + 500) / 1000
// 编译期断言: typedef char __deadtime_linear_check[(DEADTIME_REG_VAL <= 127) ? 1 : -1];
```

OIS 空闲态: MOE=0 时 4 个 MOSFET 全部可靠关断。

#### 2.2.3 防偏磁 — 周期强制偶数

```c
ticks = 72000000 / freq_Hz;
if (ticks % 2 != 0) ticks += 1;   // 强制偶数 — 正负半周对称
arr = ticks - 1;
ccr = ticks / 2;                   // 50% 整除无余数
```

#### 2.2.4 影子寄存器原子更新 (UDIS/UG)

```c
TIM1->CR1 |= TIM_CR1_UDIS;       // 暂停影子寄存器传输
TIM_SetAutoreload(TIM1, arr);
TIM_SetCompare1(TIM1, ccr);
TIM_SetCompare2(TIM1, ccr);
TIM1->EGR |= TIM_EGR_UG;        // 软件触发, 原子加载
TIM1->CR1 &= ~TIM_CR1_UDIS;     // 恢复硬件更新
```

防止 Update Event 在 ARR 和 CCR 写入之间触发导致新周期配旧占空比→偏磁→炸管。

#### 2.2.5 非阻塞软启动状态机

```
SS_IDLE ──Trigger──→ SS_SWEEP (150kHz) ──250步→ SS_DONE (100kHz)
   ↑                      │                       │
   │      ┌───────────────┘                       │
   │      ▼                                       │
   └──Stop(KEY0/KEY1) ←────────── Stop(KEY0) ─────┘
   │
   │  Fault(过流) → SS_FAULT (锁存, KEY0/KEY1复位)
   └──────────────────────────────────────────────┘
```

参数: 起始 150kHz, 目标 100kHz, 步长 200Hz, 节拍 10ms, 250 步 ≈ 2.5s.

**公开接口**:

| 函数 | 说明 |
|:---|:---|
| `PWM_Init()` | TIM1 全桥初始化, 150kHz 默认, MOE 关断 |
| `PWM_SetFrequency(Hz)` | 动态设频 (95k~150k 硬限幅) |
| `PWM_GetFrequency()` | 从 TIM1->ARR 反算当前频率 |
| `PWM_Enable()` | 先开计数器再开 MOE |
| `PWM_Disable()` | 先关 MOE 再停计数器 |
| `Inverter_SoftStart_Trigger()` | SS_IDLE→SS_SWEEP, 开 MOE |
| `Inverter_SoftStart_Task()` | 主循环调用, 10ms 时间戳步进 |
| `Inverter_SoftStart_Stop()` | 关 MOE→SS_IDLE |
| `Inverter_SoftStart_Fault()` | 紧急关断→SS_FAULT 锁存 |
| `Inverter_SoftStart_GetState()` | 返回当前状态 |
| `Inverter_SoftStart_GetCurrentFreq()` | 扫频中实时频率 |

**安全红线**: 禁止外部模块直接操作 `TIM_Cmd`/`TIM_CtrlPWMOutputs`/`TIM1->ARR`，必须通过上述接口。运行时 `s_ss_state` 写入必须通过 `Inverter_SetState()` 原子接口。

### 2.3 ADC 采集与滑动滤波

ADC1 + DMA1_Channel1 双通道循环扫描:
- PA0 = 电流 (CC6920-10A 霍尔, VREF=3.30V, I_SENSITIVITY=0.132V/A, I_OFFSET=1.65V)
- PA1 = 电压 (20:1 分压)

ADC 时钟 12MHz (72M/6)。`ADC_ConvertedValue[2]` 为 `static volatile`，DMA 后台持续刷新。

100kHz 强磁场下 DMA 瞬时值噪声严重，使用 O(1) 滑动平均:

```c
#define ADC_FILTER_WINDOW  16

uint16_t old_v = s_vbuf[s_vidx];        // 保存最旧值
s_vbuf[s_vidx] = ADC_ConvertedValue[1]; // 覆盖新值
s_vaccum += s_vbuf[s_vidx];             // 累加新值
if (s_vfilled >= ADC_FILTER_WINDOW)
    s_vaccum -= old_v;                  // 减去最旧值(O(1)替代O(N)求和)
```

`ADC_Filter_Task()` 以 2ms 独立节拍运行，与 UI/App_Net 调用频率解耦。响应延迟 32ms (16×2ms)。`Get_Real_Voltage()` / `Get_Real_Current()` 直接返回预计算值 (O(1))。

**校准时序**: `ADC_Cmd(ENABLE)` 后须等待 t_STAB ≥ 2 ADC 周期才能校准。

### 2.4 KEY 按键驱动

七态有限状态机: IDLE → DEBOUNCE → PRESSED → WAIT_RELEASE → WAIT_DOUBLE → WAIT_DOUBLE_REL。

`KEY_Task()`: 10ms 时间戳差值调度。`KEY_Get_Event()`: 阅后即焚 (0=无, 1=单击, 2=双击)。`Key_List[]` 数组 `static` 封装。

| 键 | 引脚 | 单击 | 双击 |
|:---|:---|:---|:---|
| KEY0 | PB12 (IPU) | HW初始化 / Trigger / Stop / 复位故障 | 切页 |
| KEY1 | PB13 (IPU) | Stop / +1kHz / 复位故障 | — |

---

### 2.5 OLED 显示驱动

SSD1315 128×64, 软件模拟 I2C (PA11=SCL, PA12=SDA, 开漏输出), 从机地址 0x78。8×16 ASCII 字体 (`OLED_Font.h`), 4 行 × 16 字符。

- `OLED_Clear()` 耗时 ~100ms, 仅在状态迁移/切页时调用
- 日常 200ms 刷新: 16 字符全宽行覆盖, 不调用清屏
- `OLED_ShowChar()` 含 `Line` (1~4) 和 `Char` (0x20~0x7E) 边界检查
- 支持: ShowChar, ShowString, ShowNum, ShowSignedNum, ShowHexNum, ShowBinNum, ShowFloatNum

### 2.6 UI 用户界面

双页设计, 200ms 刷新。`UI_Task()` 统筹: LED 状态更新 + 按键事件分发 + OLED 页面绘制 + LED_Status_Task 闪烁驱动。

**Page 0 — 控制面板**:
- SS_IDLE, 未连接: "Press KEY0 WiFi"
- SS_IDLE, 已连接: "Press KEY0 start"
- SS_SWEEP: 实时频率 + 进度条 `[####      ]`
- SS_DONE: 频率/电压/电流 + "K0:Stop K1:+1k"
- SS_FAULT: "!!! FAULT !!! Over Current / K0/K1: Reset"

**Page 1 — 锁屏监控**: 频率/电压/电流只读显示，按键操作屏蔽。仅 KEY0 双击可切回。

### 2.7 LED 状态指示

JTAG 禁用 (`GPIO_Remap_SWJ_JTAGDisable`), SWD (PA13/PA14) 保留, 释放 PB3/PB4 为 GPIO。

| LED | 引脚 | 有效电平 | 行为 |
|:---|:---|:---|:---|
| 心跳 | PC13 | 低 | 500ms 翻转, `LED_Task()` |
| WiFi | PB3 | 高 | 未连接→慢闪; 连接中→快闪; 已连接→常亮; `LED_Status_Task()` |
| PWM | PB4 | 高 | 快闪=SS_SWEEP, 慢闪=SS_DONE, 灭=其他 |
| Ready | PB5 | 高 | Page0 + (IDLE/DONE) + ESP8266_IsReady → 亮; FAULT → 灭 |

上电自检: PB3/PB4/PB5 全亮 ~1s 后全灭。LED 状态更新逻辑集中在 `UI_UpdateLEDs()`。

### 2.8 ESP8266 硬件驱动

V4.0 Dual-MCU: ESP8266 运行独立 Arduino MQTT 固件。STM32 端仅负责 CH_PD 硬件复位 + USART2 初始化，零 AT 指令。

**CH_PD 硬件复位流程** (`ESP8266_Init`, 阻塞 ~3s):

```
1. CH_PD(PB1) 拉低 1000ms — 模块完全放电
2. CH_PD(PB1) 拉高, 等待 2000ms — 冷启动 + RF 校准
3. USART2 初始化 + 清缓冲区
4. s_ready = 1 (ESP8266_IsReady() 返回 1)
```

**公开接口**:

| 函数 | 说明 |
|:---|:---|
| `ESP8266_Init()` | 硬件复位 + 串口初始化 |
| `ESP8266_SendString(str)` | 阻塞发送字符串 (TXE 轮询) |
| `ESP8266_GetRxFlag()` | 帧就绪标志 |
| `ESP8266_CopyRxFrame(dst, max_len)` | 临界区原子拷贝帧 (含 max_len<2 下溢保护) |
| `ESP8266_IsReady()` | 硬件就绪状态 (替代旧 s_WiFiConnected) |

**USART2 中断规则**: `USART2_IRQHandler` 必须先检查 ORE 再检查 RXNE。ISR 共享变量 (`s_RxIndex`, `g_ESP8266_RxFrameFlag`) 均为 `static volatile`。帧分隔符同时兼容 `\r` 和 `\n`。

**临界区保护**: `ESP8266_CopyRxFrame()` 在临界区内完成拷贝+清空，返回拷贝字节数。外部模块不得直接调用 `USART_ITConfig(USART2, ...)`。

### 2.9 网络应用层 (App_Net)

V4.1 Dual-MCU: 纯 JSON 串口透传，3 个公开 API。

```c
uint8_t App_Net_Init(void);          // ESP8266_Init + 标记就绪 (~3s)
void    App_Net_Task(void);          // 非阻塞周期任务 (主循环调用)
uint8_t App_Net_IsConnected(void);   // 委托 ESP8266_IsReady()
```

**App_Net_Task 子功能**:

| 子功能 | 周期 | 说明 |
|:---|:---|:---|
| JSON 遥测 | 2000ms | `{"V":xx,"I":xx,"F":xx}\n` → USART2 (SS_SWEEP 期间静默) |
| 指令接收 | 实时轮询 | `ESP8266_GetRxFlag()` → `CopyRxFrame` → `strstr` 匹配 |

**远程指令协议**:

| 指令 | 触发条件 | 动作 |
|:---|:---|:---|
| `CMD:ON` | SS_IDLE | `Inverter_SoftStart_Trigger()` |
| `CMD:OFF` | 任意 | `Inverter_SoftStart_Stop()` |
| `CMD:F_UP` | SS_DONE | `PWM_GetFrequency()+1000`, 封顶 150k |
| `CMD:F_DOWN` | SS_DONE | `PWM_GetFrequency()-1000`, 保底 95k |

**门禁保护**: `ESP8266_IsReady()` 为 0 时 `App_Net_Task` 立即返回——防止未初始化的 USART2 导致 TXE 死锁。

### 2.10 ESP8266 Arduino MQTT 固件

**文件**: `Arduino_Project/ESP8266_MQTT_Firmware/ESP8266_MQTT_Firmware.ino`

**依赖库**: ESP8266WiFi + PubSubClient (Nick O'Leary) + ArduinoJson v7 (Benoit Blanchon) + WiFiManager v2.x (tzapu)

**核心功能**:

| 功能 | 说明 |
|:---|:---|
| WiFiManager 网页配网 | 首次上电: `autoConnect()` → 无凭据→`startConfigPortal("STM32_WPT_Config")`; 手机连热点配网, 凭据存闪存, 后续自连 |
| OneNET MQTT 物模型 | `mqtts.heclouds.com:1883` (s=Studio 非 Secure); 属性上报 POST + 属性设置订阅 SET |
| JSON 协议转换 | STM32 `{"V":x,"I":x,"F":x}` → OneNET `{"id":"123","version":"1.0","params":{V:{value:x},I:{value:x},F:{value:x}}}` |
| 远程指令解析 | `Switch:true/false` → `CMD:ON`/`CMD:OFF`; `FreqAdd:true` → `CMD:F_UP`; `FreqSub:true` → `CMD:F_DOWN` |
| 属性回复 | 收到 SET 后发布 `set_reply` `{"code":200,"msg":"success"}` (解决云平台"响应超时") |
| 点动复位 | FreqAdd/FreqSub 触发后立即 POST 写回 `false`，网页端开关自动弹回 |
| 非阻塞重连 | 每 5s 检查 WiFi+MQTT，自动重连 |

**MQTT 主题**:

| 主题 | 用途 |
|:---|:---|
| `$sys/{pid}/{device}/thing/property/post` | 属性上报 (数据上行) |
| `$sys/{pid}/{device}/thing/property/set` | 属性设置 (指令下行) |
| `$sys/{pid}/{device}/thing/property/set_reply` | 属性设置应答 (确认回复) |

### 3.1 主循环调度模型

```
     ┌──────────────────────────────────────────────────────────┐
     │                  main.c while(1)                         │
     └──────────────────────────────────────────────────────────┘
                          │
      ┌──────┬──────┬──────┼──────┬──────┬──────┐
      ▼      ▼      ▼      ▼      ▼      ▼      ▼
   ┌──────┐┌──────┐┌──────┐┌──────┐┌──────┐┌──────┐
   │KEY   ││ADC   ││UI    ││App   ││Soft  ││LED   │
   │Task  ││Filter││Task  ││Net   ││Start ││Task  │
   │10ms  ││Task  ││200ms ││Task  ││Task  ││500ms │
   │      ││2ms   ││      ││实时+ ││10ms  ││      │
   │      ││      ││      ││2s    ││      ││      │
   └──┬───┘└──┬───┘└──┬───┘└──┬───┘└──┬───┘└──┬───┘
      │       │       │       │       │       │
      ▼       ▼       ▼       ▼       ▼       ▼
   七态FSM  样本推入  OLED刷新 JSON遥测 扫频步进 PC13翻转
   单击/   滑动平均  +按键分发 CMD解析  200Hz/步 心跳指示
   双击    O(1)更新  +LED状态 +指令转发 150k→100k
```

五个 Task 各自有 `static uint32_t last` 时间戳，未到周期直接 return。

### 3.2 云端→STM32 控制流

```
OneNET Studio APP
  │ 设置属性 FreqAdd=true
  ▼
ESP8266 MQTT subscribe → mqttCallback
  │ 解析 JSON → Serial.print("CMD:F_UP\n")
  │ 发布 set_reply → 回复 OneNET
  │ POST FreqAdd=false → 自动弹回
  ▼
STM32 USART2 RX → ESP8266_CopyRxFrame
  │ App_Net_Task strstr("CMD:F_UP")
  ▼
SS_DONE 门禁检查
  │ PWM_GetFrequency()+1000 → 封顶 150k
  ▼
PWM_SetFrequency → OLED "CMD: Freq +1kHz"
```

### 3.3 ADC 数据流

```
PA0(电流)/PA1(电压) → ADC1 双通道扫描 → DMA1_Channel1 循环
  → ADC_ConvertedValue[2] (后台自动刷新)
    → ADC_Filter_Task(2ms) 推入环形缓冲
      → O(1)运行累加器 → s_voltage / s_current
        → Get_Real_Voltage/Current (O(1)返回)
          → UI_Task OLED / App_Net_Task JSON遥测
```

### 4.1 STM32 串口验证

**硬件接线**:

| USB-TTL 模块 | STM32 引脚 |
|:---|:---|
| TXD | PA3 (USART2_RX) |
| RXD | PA2 (USART2_TX) |
| GND | GND |

**步骤**:

1. Keil MDK 编译 `Keil_Project/Project.uvprojx`，ST-Link 烧录到 STM32
2. 串口助手配置 **115200 bps / 8N1**，选择对应 COM 口
3. 上电后 OLED 显示 `Wireless Charge` → `Press KEY0 WiFi`
4. **按下 KEY0**: OLED 显示 `HW Init...` → 约 3 秒后 `WiFi: READY`
5. 串口助手每 **2 秒** 收到: `{"V":12.50,"I":1.23,"F":100000}`
6. 发送以下字符串测试:

| 发送内容 | 预期结果 |
|:---|:---|
| `CMD:ON\n` | OLED `CMD: Remote ON`，逆变器开始扫频 |
| `CMD:OFF\n` | OLED `CMD: Remote OFF`，逆变器关断 |
| `CMD:F_UP\n` | OLED `CMD: Freq +1kHz`，频率 +1kHz (仅 SS_DONE) |
| `CMD:F_DOWN\n` | OLED `CMD: Freq -1kHz`，频率 -1kHz (仅 SS_DONE, 下限 95k) |

> `\n` 换行符不可省略。F_UP/F_DOWN 仅在 SS_DONE 状态生效。

**无串口模块简化验证**: KEY0 单击后 PB5 常亮, PB3 常亮 (WiFi Ready), KEY0 再次单击触发扫频。

### 4.5 STM32 + ESP8266 联调

**完整接线**:

```
STM32 PA2 (TX) ──── ESP8266 RXD
STM32 PA3 (RX) ──── ESP8266 TXD
STM32 GND      ──── ESP8266 GND
STM32 PB1      ──── ESP8266 CH_PD/EN
```

> ESP8266 需独立 3.3V 供电 (AMS1117-3.3, ≥500mA)，不可从 STM32 板取电。

**步骤**:

1. 先给 ESP8266 上电，等 ~5s WiFi + MQTT 连好 (OneNET 显示在线)
2. 再给 STM32 上电
3. STM32 按 KEY0 → CH_PD 复位 ESP8266 → USART2 初始化 → OLED `WiFi: READY`
4. STM32 每 2s 发 JSON → 串口→ESP8266→MQTT→OneNET 数据流可见
5. OneNET 下发 `Switch=true` → ESP8266→STM32 `CMD:ON` → 逆变器扫频
6. OneNET 下发 `FreqAdd=true` → `CMD:F_UP` → 频率 +1kHz → FreqAdd 自动复位

### 4.6 故障排查

| 现象 | 可能原因 | 解决方法 |
|:---|:---|:---|
| Keil 编译报错 `App_Net.h` 找不到 | 头文件丢失 | 确认 `Keil_Project/User/App_Net.h` 存在 |
| STM32 无 JSON 输出 | `ESP8266_IsReady()=0` | 按 KEY0 触发 `App_Net_Init()` |
| OLED 显示 `WiFi: DISCONN` | 未按 KEY0 初始化 | 按 KEY0 触发硬件初始化 |
| ESP8266 反复重启 (串口重复 Booting) | 供电不足 / WiFiManager 无凭据 | 独立 3.3V≥500mA; 烧录最新固件 (含 startConfigPortal 兜底) |
| ESP8266 不连 WiFi | 无已存凭据 / 2.4GHz 频段 | 手机搜 `STM32_WPT_Config` 配网 (无密码) |
| WiFi 已连但 OneNET 离线 (MQTT rc=-2) | MQTT 服务器地址错误 | 确认 `mqtts.heclouds.com:1883` (s=Studio 非 TLS) |
| OneNET 下发命令"响应超时" | 缺少 set_reply | 确认 ESP8266 固件包含 `MQTT_TOPIC_PROPERTY_SET_REPLY` |
| OneNET 下发 Switch 无反应 | JSON 格式不匹配 | 确认固件支持布尔值 `Switch:true/false` |
| STM32 收不到 CMD:ON | TXD/RXD 交叉接反 | 交换 PA2/PA3 与 ESP8266 的接线 |
| 云端 FreqAdd 触发后不复位 | 点动复位失效 | 确认固件末尾有 POST false 逻辑 |
| ESP8266 烧录失败 | GPIO0 未拉低 | GPIO0 可靠接 GND 后上电 |
| 烧录后不运行 | 仍在烧录模式 | 断开 GPIO0-GND, 重新上电 |
| `__deadtime_linear_check` 编译报错 | DEADTIME_NS 过大 | 减小死区值或增大 CKD 分频 |
