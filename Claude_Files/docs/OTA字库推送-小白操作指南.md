# OTA 字库推送 — 小白操作调试指南

> 适用版本: V4.3.1 | 更新日期: 2026-06-23
>
> 本指南假设你已烧录好固件，只需要通过 WiFi 无线更新 TFT 屏幕上的中文字库。
> **不需要拆外壳、不需要杜邦线、不需要编程器。**

---

## 一、你需要准备什么

| 物品 | 说明 |
|:---|:---|
| **WPT 设备** | 已烧录 V4.3.1 固件，TFT 能显示主菜单 |
| **一台电脑** | Windows 10/11，连在**同一个 WiFi** 下 |
| **Python** | 3.6 以上版本（Anaconda 或 python.org 下载均可） |

---

## 二、第 0 步：确认 Python 能用

打开 **命令提示符**（按 `Win+R`，输入 `cmd`，回车）：

```bash
python --version
```

期望看到类似 `Python 3.7.0`。如果提示"不是内部命令"：

1. 去 [python.org](https://python.org) 下载 Python 3.x
2. 安装时**勾选** `Add Python to PATH`（非常重要！）
3. 重新打开命令提示符再试

---

## 三、第 1 步：确保设备处于主菜单

调设备**不是扫频页、不是运行页、不是故障页**。

TFT 屏幕应该显示主菜单，类似：

```
┌──────────────────────┐
│  ◆ 启动运行           │
│    综合监测           │
│    无线配网           │
│    系统设置           │
│                      │
│  ON:确定  PAGE:返回   │
└──────────────────────┘
```

如果设备在运行中 → 按 **ON/OFF 键** 停机回到主菜单。

---

## 四、第 2 步：找到 ESP8266 的 IP 地址

### 方法 A：从 TFT 屏幕看（推荐）

1. 在主菜单按 **PAGE 键** 翻到 `无线配网`
2. 按 **ON 键** 进入
3. 屏幕会显示当前 WiFi 连接状态和 **IP 地址**

记下这个 IP，例如 `192.168.1.100`

### 方法 B：从路由器后台看

1. 浏览器输入路由器管理地址（通常是 `192.168.1.1` 或 `192.168.0.1`）
2. 登录（密码一般在路由器底部贴纸上）
3. 找到 **DHCP 客户端列表** 或 **已连接设备**
4. 找名为 `ESP_` 开头的设备，记下 IP

---

## 五、第 3 步：运行推送脚本

打开命令提示符，输入以下命令（**把 IP 换成你上一步找到的**）：

```bash
cd "D:\Claude Code Project\WPT_PWM_V4.0_ONENET_TFT\Claude_Files\tools"
python ota_font_push.py --ip 192.168.1.100
```

### 期望看到的内容

```

[Build] ASCII x95 + CJK x76 → 4352B (17 pages)
[Connect] TCP 192.168.1.100:8266 OK
  [4/17] ok=4 err=0
  [8/17] ok=8 err=0
  [12/17] ok=12 err=0
  [16/17] ok=16 err=0
  [17/17] ok=17 err=0
[Done] Font updated (17 pages, 17 ok)
```

TFT 屏幕会同步显示进度 → 完成后显示"字库更新成功"。

整个过程约 **3-5 秒**。

## 六、故障排查

### ❌ 错误：`Cannot connect to ESP8266`

```
[Error] Cannot connect to ESP8266: timed out
[Hint] Confirm PC and ESP8266 are on same WiFi
```

**原因**：电脑连不上 ESP8266 的 TCP Server。

**排查步骤**：

1. **确认电脑和 ESP 在同一 WiFi**
   - 电脑：右下角 WiFi 图标 → 属性 → 查看连接的 WiFi 名称
   - ESP：TFT `无线配网` 页面 → 查看连接的 WiFi 名称
   - **必须相同**

2. **确认 ESP8266 已正常联网**
   - TFT 主菜单右上角 WiFi 图标是否常亮（不闪烁）
   - 如果 WiFi 图标闪烁或熄灭 → 等它联网稳定后再试

3. **测试连通性**

   ```bash
   ping 192.168.1.100
   ```

   如果 ping 不通，说明 IP 不对或不在同一网络。

4. **检查防火墙**
   - Windows 防火墙可能拦截 TCP 8266 端口
   - 暂时关闭防火墙再试：
     `控制面板 → Windows Defender 防火墙 → 启用或关闭 Windows Defender 防火墙 → 关闭`

---

### ❌ 错误：`STM32 not ready`

```
[Error] STM32 not ready (reply: )
```

**原因**：STM32 没有进入 OTA 模式。

**排查步骤**：

1. **确认设备处于主菜单（IDLE 态）**
   - 如果不是主菜单 → 按 ON/OFF 键停机
   - 如果是故障页 → 按 ON 键清除故障

2. **确认 USART2 通信正常**
   - TFT 主菜单右上角 MQTT 图标是否常亮（绿色）
   - 如果 MQTT 图标熄灭 → ESP8266 串口通信可能异常 → 尝试重启设备

3. **如果以上都正常**，重新运行推送脚本（重试即可）

---

### ❌ 错误：某页推送失败

```
  [Fail] seq=3: OTA:ERR:3,B64LEN
```

**原因**：WiFi 丢包导致数据损坏，或 Base64 解码失败。

**处理**：
- 脚本会自动重试 3 次
- 如果 3 次全失败 → **重新运行整个脚本**即可
- 如果反复在同一页失败 → 靠近路由器再试（WiFi 信号弱）

---

### ❌ TFT 屏幕花屏/乱码

**原因**：字库数据损坏（极少见，通常由推送中途断电导致）。

**恢复出厂字库（USB-TTL 方式）**：

1. USB-TTL 模块连接 STM32
2. 打开 Keil uVision → 打开 `Keil_Project/Project.uvprojx`
3. 按 **F7** 编译 → 按 **F8** 烧录
4. 烧录完成后设备自动重启 → STM32 上电检测到字库校验失败 → 自动从片内 ROM 搬运 76 汉字 + 95 ASCII 到 W25Q128 Flash
5. TFT 恢复正常显示

> **约 500ms 后屏幕恢复正常** — STM32 自动完成了所有字库搬运工作。

## 七、常见问题（FAQ）

**Q: 为什么推送要设备处于主菜单（IDLE）？**
A: 为了安全。写 Flash 期间不能发波（PWM 关），否则 12V 功率电路的电磁干扰可能损坏 Flash 数据。

**Q: 推送过程中断电能恢复吗？**
A: 不能自动恢复。重新上电后 STM32 检测到字库损坏 → 自动从片内 ROM 恢复 76 汉字 + 95 ASCII。如果需要更新字库，重新运行推送脚本。

**Q: 可以推送自己做的字库吗？**
A: 当前 Phase A 只支持现有的 76 汉字 + 95 ASCII。自定义字库需要 Phase B（GB2312 全字库 6763 字），后续升级。

**Q: 推送速度为什么这么快？**
A: Phase A 只有 4KB（17 页），~3 秒传完。Phase B 全字库 668KB 大约需要 70 秒。

**Q: 需要安装什么 Python 库吗？**
A: 不需要。推送工具只用了 Python 标准库（`socket`, `base64`, `struct`, `re`, `argparse`），零外部依赖。
