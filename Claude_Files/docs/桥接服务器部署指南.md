# WPT 桥接服务器部署指南 (ngrok 方案)

**版本**: V1.0 | **日期**: 2026-05-24

---

## 1. 为什么需要桥接服务器

微信小程序真机对 WebSocket 有严格限制 — 只能用 `wss://` 连接已备案的可信域名。EMQX 公共 Broker 的 TLS 证书不在微信白名单内，`wx.connectSocket` 会直接失败。

```
错误方案 (不可行):
  微信小程序 ──wss── EMQX Broker    ← 微信拒绝非白名单域名

正确方案 (桥接):
  微信小程序 ──HTTPS── ngrok ── 桥接服务器 ──MQTT── EMQX ── ESP8266
                        (Node.js)              (明文 1883)
```

**桥接服务器做了什么**:
- 连接 EMQX MQTT Broker，订阅 `wpt/20260001/data` 获取遥测
- 暴露 HTTP `GET /data` 接口 — 小程序拉取数据
- 暴露 HTTP `POST /cmd` 接口 — 小程序下发控制指令
- ngrok 将本地 HTTP 服务映射到公网 HTTPS，小程序可直接访问

## 2. 架构与数据流

```
┌─────────────┐    HTTP 轮询 (2s)    ┌─────────────┐
│  微信小程序   │ ◄──────────────────► │   ngrok 隧道  │
│  (真机/模拟器) │    GET  /data       │  (HTTPS)     │
│             │    POST /cmd        └──────┬──────┘
└─────────────┘                           │ localhost:3000
                                    ┌──────┴──────┐
                                    │  桥接服务器    │ Node.js
                                    │  Express     │ port 3000
                                    └──────┬──────┘
                                           │ MQTT (1883)
                                    ┌──────┴──────┐
                                    │  EMQX Broker │ broker.emqx.io
                                    └──────┬──────┘
                                           │ MQTT
                                    ┌──────┴──────┐
                                    │  ESP8266     │
                                    │  + STM32     │
                                    └─────────────┘
```

**轮询间隔 2s 的原因**: ngrok 免费版有请求速率限制（~1500 次/小时），500ms 轮询会触发 ERR_CONNECTION_CLOSED。2s 间隔将请求量控制在 ~1800 次/小时，略超限额但 ngrok 通常允许短暂突发。

## 4. DNS 污染问题 (重要)

### 4.1 现象

部分教育网/企业网环境（如 CERNET）DNS 服务器会将 ngrok 域名投毒解析到 `127.0.0.1`，导致 ngrok 无法连接：

```
nslookup connect.ngrok-agent.com
→ Addresses: ::1, 127.0.0.1    # ← 错误！应为公网 IP
```

ngrok 日志报错: `failed to dial ngrok server: dial tcp [::1]:443: ... connection refused`

### 4.2 修复

通过修改 hosts 文件，绕过 DNS 解析直接用真实 IP 连接：

```bash
# 1. 用 Google DNS 查询真实 IP
nslookup connect.ngrok-agent.com 8.8.8.8

# 2. 管理员权限编辑 hosts
# Windows: C:\Windows\System32\drivers\etc\hosts
# 添加一行:
3.1.215.86 connect.ngrok-agent.com

# 3. 刷新 DNS 缓存
ipconfig /flushdns

# 4. 验证
ping connect.ngrok-agent.com
# 应返回 3.1.215.86 而非 127.0.0.1
```

> **备选 IP**: 如果 `3.1.215.86` 失效，从 Google DNS 查询结果中换一个其他 IP（如 `54.169.118.152`、`122.248.247.123`）。

## 5. 操作步骤

### 5.1 一键脚本启动 (推荐)

以管理员权限打开 PowerShell，执行：

```powershell
cd Claude_Files\tools
powershell -ExecutionPolicy Bypass -File start_bridge.ps1
```

脚本会自动：
1. 检查 Node.js 和 ngrok 是否安装
2. 释放被占用的 3000 端口
3. 启动桥接服务器 (Node.js)
4. 启动 ngrok 公网隧道
5. 提取公网 URL 并验证数据接口

启动成功后显示：
```
========================================
  隧道已就绪!
========================================
  公网地址: https://xxx-xxx-xxx.ngrok-free.dev
  数据接口: https://xxx-xxx-xxx.ngrok-free.dev/data
  控制接口: https://xxx-xxx-xxx.ngrok-free.dev/cmd
  健康检查: https://xxx-xxx-xxx.ngrok-free.dev/health

[验证] 测试公网数据接口...
  数据接口 OK — V=0 I=0 F=150000

  微信小程序 BRIDGE 地址:
  const BRIDGE = 'https://xxx-xxx-xxx.ngrok-free.dev';
========================================
```

**停止**: 按 `Ctrl+C` 或运行 `stop_bridge.ps1`。

### 5.2 手动操作 (备选)

#### 步骤 1: 启动桥接服务器

```bash
cd 安卓app\server
node bridge.js
```

输出:
```
[Bridge] Connected to EMQX
[Bridge] Subscribed to wpt/20260001/data
[Bridge] Server running on http://localhost:3000
```

#### 步骤 2: 启动 ngrok 隧道

新开一个终端窗口：

```bash
ngrok http 3000
```

输出:
```
Forwarding  https://xxx-xxx-xxx.ngrok-free.dev -> http://localhost:3000
```

#### 步骤 3: 验证

```bash
curl -H "ngrok-skip-browser-warning: true" https://xxx-xxx-xxx.ngrok-free.dev/data
```

应返回 JSON: `{"voltage":0,"current":0,"frequency":150000,"updated":...}`

#### 步骤 4: 更新小程序地址

编辑 `安卓app/pages/index/index.js`，将 `BRIDGE` 改为 ngrok 输出的公网地址：

```js
const BRIDGE = 'https://xxx-xxx-xxx.ngrok-free.dev';
```

#### 步骤 5: 停止

```bash
# Ctrl+C 停止 ngrok
# Ctrl+C 停止桥接服务器
```

## 6. 小程序配置

`安卓app/pages/index/index.js` 中的关键配置：

```js
const BRIDGE = 'https://kindred-whisking-varnish.ngrok-free.dev';
const POLL_MS = 2000;  // 轮询间隔 (ngrok 免费版建议 2000ms)

// 所有请求必须加 ngrok 跳过浏览器警告头
header: { 'ngrok-skip-browser-warning': 'true' }
```

**每次 ngrok 重启后**，如果域名变了（免费版域名可能变化），需同步更新 `BRIDGE` 地址。

> **固定域名技巧**: 如果 ngrok 分配的域名不变（如 `kindred-whisking-varnish`），则无需更改。

## 7. 故障速查

| 现象 | 可能原因 | 解决 |
|:---|:---|:---|
| ngrok `ERR_NGROK_4018` | 账号未验证或 authtoken 无效 | `ngrok config add-authtoken <token>` |
| ngrok `connect: connection refused` | DNS 污染 | 按第 4 节修改 hosts |
| ngrok `ERR_NGROK_334` | 同一域名已有隧道在运行 | 杀残留进程或等待 2 分钟自动释放 |
| 小程序 `request:fail` | 手机无法访问公网 | 检查手机网络 + ping 域名 |
| 小程序 `connected:false` | 桥接服务器未启动 | 检查 `localhost:3000/health` |
| 小程序数据显示但控制无反应 | MQTT 下行链路断开 | 确认 ESP8266 在线 + EMQX 已连接 |
| `curl: (52) Empty reply` | ngrok 免费版请求过载 | 确保轮询间隔 >= 2s |
| 小程序数据延迟高 (>5s) | 网络链路延迟 | 正常现象，2s 轮询 + HTTP 往返 |

## 9. 从 ngrok 迁移到 Railway

ngrok 免费版有以下限制，正式上线建议迁移到 Railway.app：

| 对比 | ngrok 免费版 | Railway.app |
|:---|:---|:---|
| 域名 | 每次启动可能变化 | 固定域名 |
| 速率限制 | ~1500 req/h | 无 |
| 稳定性 | 中等 | 高 |
| 费用 | 免费 | 免费额度 (5 美元/月) |
| 需本地运行 | 是 | 否 (云端) |

**迁移步骤** (简要):

1. 将 `安卓app/server/` push 到 GitHub
2. Railway 新建项目 → Deploy from GitHub Repo
3. 设置启动命令: `node bridge.mjs`
4. 获取 Railway 分配的 HTTPS 域名
5. 更新小程序的 `BRIDGE` 地址

> 迁移后不再需要 ngrok，小程序的 HTTPS 请求直接到 Railway 服务器，无需本地运行任何程序。
