# WPT 微信小程序开发总结

**版本**: V4.2.1 | **日期**: 2026-05-24

---

## 1. 项目概述

基于微信小程序 + Node.js 桥接服务器的 WPT 全桥逆变器远程监控与控制系统。小程序通过 HTTPS 访问桥接服务器，桥接服务器通过 MQTT 连接 EMQX 公共 Broker，实现与 ESP8266/STM32 双 MCU 硬件系统的实时通信。

## 2. 架构数据流

```
STM32 ──Serial── ESP8266 ──MQTT── OneNET (物模型)
                        │
                        ├──MQTT── EMQX (broker.emqx.io)
                        │            │
                        │     ┌──────┴──────┐
                        │     │ 桥接服务器    │ ← Node.js Express + mqtt.js
                        │     │ GET  /data   │   端口 3000
                        │     │ POST /cmd    │
                        │     └──────┬──────┘
                        │            │ HTTPS (ngrok / Railway)
                        │     ┌──────┴──────┐
                        │     │ 微信小程序    │ ← wx.request 轮询
                        │     │ 显示 + 控制   │   2 秒间隔
                        │     └─────────────┘
                        │
                        └──Serial── STM32 ← CMD:ON/OFF/F_UP/F_DOWN
```

## 4. 核心功能

### 4.1 数据显示

| 字段 | 来源 | 格式化 |
|:---|:---|:---|
| 电压 (V) | EMQX → 桥接 → 小程序 | `toFixed(2)` |
| 电流 (A) | EMQX → 桥接 → 小程序 | `toFixed(2)` |
| 频率 (kHz) | EMQX → 桥接 → 小程序 | `Math.floor(F / 1000)` |
| 系统状态 | 程序推断 | IDLE/SWEEP/DONE/FAULT |

### 4.2 远程控制

| 指令 | 触发条件 | HTTP API |
|:---|:---|:---|
| CMD:ON | IDLE 状态 | `POST /cmd {cmd:"CMD:ON"}` |
| CMD:OFF | SWEEP/DONE 状态 | `POST /cmd {cmd:"CMD:OFF"}` |
| CMD:SETFREQ:<Hz> | DONE 状态 | `POST /cmd {cmd:"CMD:SETFREQ:100000"}` |

### 4.3 状态推断

小程序根据遥测数据自动推断系统状态：
- V=0 → IDLE（待机）
- V>0 且频率不稳定 → SWEEP（扫频中）
- V>0 且频率 2 次不变 → DONE（运行中）

## 5. 关键技术决策

### 5.1 为什么不用 WebSocket 直连

微信小程序真机强制 HTTPS WebSocket（wss://），EMQX 公共 Broker（broker.emqx.io）的 TLS 证书不被微信信任，`wx.connectSocket` 连接失败。改用 HTTP 轮询 + 桥接服务器方案。

### 5.2 桥接服务器

- **本地开发**：Node.js + Express + mqtt.js，端口 3000
- **公网访问**：ngrok 隧道（临时测试）或 Railway.app 部署（永久）
- **轮询间隔**：2 秒（平衡实时性与 ngrok 免费额度）

### 5.3 频率滑块 vs 加减按钮

V4.2 将 ±1kHz 加减按钮改为频率滑块 (95-150kHz, 步长 1kHz)，指令从 `CMD:F_UP`/`CMD:F_DOWN` 改为 `CMD:SETFREQ:<Hz>`。滑块松手后即时发送目标频率，STM32 直接设置到指定值，替代逐次加减。优势：远程端不再依赖"当前频率"状态，消除重复点击导致的 ±2kHz 频偏问题。

### 5.4 即时反馈

滑块松手后立即更新 UI 并弹 Toast 提示，不等遥测确认，防止用户重复操作。

## 6. 已知问题与改进方向

| 问题 | 原因 | 改进方案 |
|:---|:---|:---|
| ~~频率显示 ±2kHz~~ | ~~无即时反馈致重复点击~~ | ✅ 已解决 — V4.2 改用 SETFREQ 滑块直接设定 |
| 频率量化误差 | TIM1 整数分频无法精确到每 kHz | 可接受 (~280Hz @ 100kHz)，OLED/Web/小程序均截断一致 |
| ngrok 隧道不稳 | 免费版带宽/请求限制 | 部署 Railway.app 或自有服务器 |
| 状态推断偶尔误判 | 谐振腔残压/扫频频率波动 | 增加 V 阈值判断 |
| 小程序需域名白名单 | 微信 WebSocket/HTTPS 要求 | 正式上线时配置合法域名 |

## 7. 与 Web Dashboard 对比

| 方面 | Web Dashboard (APP/) | 微信小程序 (安卓app/) |
|:---|:---|:---|
| 通信方式 | WebSocket 直连 EMQX | HTTP 轮询桥接服务器 |
| 实时性 | <500ms 推送 | 2s 轮询 |
| 控制功能 | 无（已简化为只读） | 启停 + 调频 |
| 平台 | 浏览器 | 微信 |
| 部署 | `npm run dev` | 微信开发者工具 |
| 依赖 | 无 | 桥接服务器 |
